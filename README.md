# HeadOrbit

A tiny macOS menu bar app that reads head motion from your AirPods and turns it into small, useful things on screen.

Look away from the screen, and it blurs. Slouch until your chin comes up, and it nudges you to sit straight. That's it for now.

> **Status: an experiment, made for fun.**
> Inspired by [this post by @bryllim_](https://x.com/bryllim_/status/2099049704822907277). This is a weekend-project-grade tool, not a product. Expect rough edges.

## This fork: 0.1.6 (12)

This repository maintains improvements to [Cogria-AI/HeadOrbit](https://github.com/Cogria-AI/HeadOrbit), based on upstream v0.1.5. The original author, artwork, and MIT license are retained. This remains experimental software.

- **Automatic recovery after reconnecting:** a click, keystroke, or scroll starts a short observation period. Natural small head movements are allowed; repeated clicks are unnecessary.
- **Full pose calibration:** Yaw, Pitch, and Roll share one relative attitude reference. Pitch and posture reminders resume after a suitable automatic reference or manual recentering.
- **More reliable reconnection handling:** observe Bluetooth input/output changes, retry a bounded number of times, and distinguish audio connectivity from actual motion data.
- **Clearer controls:** `⌃⌥⌘C` to sit straight and recenter, recovery status/reasons, motion diagnostics export, and the complete version/build number in the lower-left corner.

See the [changelog](CHANGELOG.md), [recovery guide and limitations](docs/RECOVERY.md), and [validation scope](docs/VALIDATION.md).

**Build 12:** brief delivery delays pause effects and preserve the existing calibration. Buffered samples cannot recenter the app; a real sensor discontinuity or five seconds without fresh data invalidates the reference.

## Features

- **Blur when you look away.** Turn your head left or right past a set angle and the whole screen softly blurs. Look back and it clears.
- **Posture reminder.** Calibrate while sitting straight. When you slump and your head tilts up to keep looking at the screen, HeadOrbit blurs the screen and shows a reminder until you sit up. Press `Esc` to dismiss and pause it for a minute.
- **Live head angles** in the menu, so you can see what the earbuds see.
- **One-click calibration.** Whatever pose you're in when you click becomes "forward".
- **Menu bar status icon.** Outline when nothing is connected, filled when your earbuds are streaming.
- **English / 中文 / 日本語**, follows the system language, switchable in the menu.
- **Light / Dark / System** appearance for the panel.

The app does not upload data or use the network, camera, microphone recording, or screen recording. Automatic recovery reads only the age of recent input events, never their contents. Motion diagnostics stay in memory until you explicitly export a CSV; review that file before sharing it.

## Requirements

- macOS 14 Sonoma or later
- AirPods or Beats that support head tracking, for example AirPods Pro (any generation), AirPods 3 / 4, AirPods Max, Beats Fit Pro, Powerbeats Pro 2
- The earbuds must be connected to **this Mac**. If they auto-switch to your iPhone, the Mac stops receiving motion data.
- Works with one earbud or both.

## Install

### Option 1: download the app

Download only from [this fork’s Releases](https://github.com/jimzzzjones/HeadOrbit/releases), when a packaged build is available. Read its release notes for architecture, version, and signing status. Source archives generated by GitHub are not installable apps. Until a binary is listed, use the source build below.

Builds are ad-hoc signed and **not Apple-notarized**. macOS may block a downloaded app; review its origin and use the macOS Privacy & Security approval flow only if you trust it.

### Option 2: build from source

Install Apple Command Line Tools with Swift 5.9 or newer, then:

```bash
git clone https://github.com/jimzzzjones/HeadOrbit.git
cd HeadOrbit
./script/test.sh
./script/build_and_run.sh --build
open dist/HeadOrbit.app
```

This builds for the current Mac's architecture. You can place the bundle outside an iCloud-synced directory with `HEADORBIT_APP_BUNDLE=/private/tmp/HeadOrbit.app ./script/build_and_run.sh --build`. The script defaults to `/Library/Developer/CommandLineTools`; set `DEVELOPER_DIR` if using a full Xcode installation.

For the Xcode project, install Xcode 15+ and XcodeGen, then use `./build.sh`. `./package.sh` creates an ad-hoc signed DMG. See [Contributing](CONTRIBUTING.md) for checks.

### First launch

macOS asks for **Motion & Fitness** access. Allow it, that's the only permission HeadOrbit needs. HeadOrbit normally lives in the menu bar, with no Dock icon. Developers can open a persistent settings window using `open dist/HeadOrbit.app --args --show-settings`.

## Usage

1. Put on your AirPods and make sure they're connected to the Mac.
2. Click the HeadOrbit icon in the menu bar. The header should read **Tracking (left)** or **Tracking (right)**, telling you which earbud is providing data.
3. With **Quiet recovery after reconnecting** enabled, face the screen and click, type, or scroll once, then continue naturally. Small movements are allowed while a stable reference is collected. To set an exact reference immediately, sit straight and click **Sit straight & recenter**, or press `⌃⌥⌘C`.
4. Turn on the features you want and tune the sliders.

## Configuration

### Blur when looking away

| Setting | What it does | Default |
|---|---|---|
| Trigger angle | How far left or right your head must turn before the screen counts as "not being looked at" | 35° |
| Delay before blur | How long you must stay turned away before it triggers, so a quick glance doesn't count | 0.6 s |
| Dimming | Extra darkening on top of the blur | 0.15 |

### Posture reminder

| Setting | What it does | Default |
|---|---|---|
| Trigger angle | Reminds when head pitch rises above this value (head-up is positive, measured from your calibrated pose). Set it to 0 or below if you calibrated while already slouching a bit | +15° |
| Hold before reminding | How long the bad posture must persist. Slouching happens slowly, so this is measured in seconds, not fractions | 5 s |

The reminder is off by default because it only makes sense after calibrating. While it's showing, press `Esc` or click **Dismiss, pause 1 min** in the menu.

### Language and appearance

Both live at the bottom of the menu. Language defaults to Chinese or Japanese if your system uses one of them, English otherwise.

## Calibration limits

Automatic recovery estimates a reference from your current stable pose; it cannot know where your screen is or prove that you are sitting upright. It freezes that reference after recovery. It is not continuous drift correction. If the reference feels off, face the screen, sit straight, and recenter manually. Before a valid reference exists, effects pause; live Pitch is labeled “not centered.”

## Troubleshooting

**"No head-tracking headphones"** while wearing AirPods
- Check they're connected to the Mac, not your iPhone (Control Center → Sound).
- Take them out and put them back in. Motion data only streams while they're worn.
- Make sure the model supports head tracking (see Requirements).

**Bluetooth audio connected, but no motion data**
- Keep the headphones on and connected to this Mac. Audio and motion can resume at different times.
- After automatic retries finish, use **Reconnect**. Briefly playing audio on the Mac helped in one observed session; it is not a guaranteed fix. HeadOrbit does not play audio or change the route automatically.

**Recovery keeps waiting**
- Face the screen and click, type, or scroll once. Activity inside HeadOrbit counts too.
- Small natural motion is fine. Larger turns, inconsistent direction, or data gaps can prevent recovery. After the observation expires and the brief cooldown ends, new activity starts another attempt.
- Use `⌃⌥⌘C` for immediate manual calibration. See [Recovery](docs/RECOVERY.md).

**Motion & Fitness access denied**
- System Settings → Privacy & Security → Motion & Fitness → enable HeadOrbit.
- If you rebuild the app yourself, macOS may ask again. That's expected with a locally signed build.

**The blur looks like a flat dark sheet instead of blur**
- HeadOrbit uses a WindowServer blur that Apple doesn't document. If a future macOS removes it, the overlay falls back to plain dimming.
